# SatyaBid — 90-Second Demo Script

Total: 90 seconds. Narration is calm, official, no hype. Screen actions in
**bold**. UI must support this exact sequence (§10 of UI_UX_SPEC).

| Time | Visual | Voiceover |
|---|---|---|
| 0–12s | **S1**: click **"Run demo scrutiny"**. Stepper ticks: ingest → blueprint → checks → collusion → verdicts. | "A GeM tender for 500 desktops. Five bids. SatyaBid scrutinises every one — deterministically, with evidence for each verdict." |
| 12–35s | **S3 dashboard**: KPIs count up; ring banner; L1 banner; verdict table. | "One responsive bidder. Three rejected. One ring flagged — two bidders sharing directors, a phone, an address, and near-identical prices." |
| 35–55s | **S4 Bidder B** → expand **R2** → **"View evidence"** → **S5** split pane: clause vs certificate. | "Every verdict traces to proof. The tender demands ₹1.5 crore turnover; the bidder claims ₹2.4 — but their own CA certificate averages ₹1.1. Rejected, with the evidence on screen." |
| 55–75s | **S6 graph**: C–D edge glowing HIGH; expand pair → 5 signals listed. | "Cross-bidder analytics maps the cartel: shared directors, shared phone, prices within 0.7 percent. This is the collusion no manual check catches." |
| 75–90s | **S7 audit**: click **"Verify chain"** → green confirmation. | "And every step is sealed in a tamper-evident ledger. SatyaBid — every verdict carries its evidence." |

**Rehearsal notes:**
- Mute system notifications. 1366×768 capture.
- Do one full dry run; the stepper timing is real (engine speed), not edited.
- If anything lags, cut the S4 expand — never cut the evidence pane or the
  audit verify; those are the two trust moments.
